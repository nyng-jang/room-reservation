# 조사실 예약 시스템 (시연용)

> 가상 데이터로 동작하는 시연판입니다. 실제 기관 시스템이 아니며, 데이터는 매일 자정(KST) 초기 상태로 돌아갑니다.
>
> 데모: https://room-reservation-demo-zeta.vercel.app (초대코드 필요)

## 배경

전파관리소 인턴 시절, 조사실 1개를 여러 조사관이 나눠 쓰면서 예약이 겹치거나 확인이 번거로운 문제가 있었습니다.
당시 생성형 AI로 프로토타입을 만들었지만, 데이터를 함께 저장·공유하려면 서버와 DB가 필요했고 기관 인프라 적용 절차 때문에 배포 단계에서 멈췄습니다.
이 저장소는 그 이후 직접 배포와 DB 구성을 익혀, 같은 요구사항을 실제로 동작하는 서비스로 완성한 버전입니다.

## 요구사항

| 항목 | 내용 |
| --- | --- |
| 용도 | 미인증 방송통신기자재 중고거래(1년 이내) 전파법 위반 조사 — 목적이 하나라 입력받지 않고 고정 표시 |
| 공간 | 조사실 1개 고정 |
| 운영 | 평일 09:00–18:00, 1시간 단위 |
| 예약 | 생성·수정·삭제, 시간 중복 불가 |
| 조사관 | 추가·이름 변경·삭제 (인원이 자주 바뀜) |
| 공유 | 여러 명이 폰으로 동시에 사용, 변경 사항 실시간 반영 |
| 접근 | 팀 공용 초대코드 1개 (개별 가입 없이 단톡방 공지로 배포) |

## 구조

```
폰/PC 브라우저 (React + Tailwind)
   │  src/lib/api.js  ← 데이터 레이어 (이 파일만 바꾸면 DB 교체 가능)
   ▼
Supabase (Postgres)
   ├─ public.rr_* 함수         모든 요청이 초대코드를 확인한 뒤에만 실행
   ├─ room_res.settings        초대코드 (bcrypt 해시로만 저장)
   ├─ room_res.investigators   조사관 (삭제 = 비활성 처리, 과거 기록 보존)
   ├─ room_res.reservations    예약
   │    · 중복 방지: EXCLUDE 제약 (같은 날짜 + 시간 범위 겹침 금지)
   │    · 평일·운영시간 검사: CHECK 제약
   └─ Realtime Broadcast       "바뀌었음" 신호만 전송 → 각자 코드로 다시 조회
Vercel
   ├─ 정적 사이트 호스팅
   └─ Cron (매일 00:00 KST) → /api/reset → 시연 데이터 초기화
```

### 설계 포인트

- **초대코드는 화면이 아니라 DB가 확인합니다.** 사이트 코드는 누구나 열어볼 수 있어서, 화면에서만 비밀번호를 검사하면 의미가 없습니다. 테이블 직접 접근을 막고, 모든 조회·수정을 코드 확인 함수로만 열었습니다. 실시간 신호에도 데이터는 싣지 않습니다.
- **중복 예약은 DB가 막습니다.** 두 사람이 같은 시간을 동시에 눌러도 화면 검사만으로는 막을 수 없어서, Postgres 배제 제약으로 한 명만 저장되게 했습니다.
- **조사관 삭제는 비활성 처리입니다.** 인원이 자주 바뀌어도 지난 예약 기록이 깨지지 않습니다.
- **데이터 레이어 분리.** 기관 내부 서버나 다른 DB로 옮길 때 `src/lib/api.js`만 교체하면 됩니다.

## 화면 설계 (UI/UX)

처음 쓰는 사람도 설명 없이 쓸 수 있도록 Nielsen의 10가지 사용성 원칙과 WCAG 터치 영역 기준(44px)을 기준으로 설계했습니다. 형태(둥근 카드·알약 버튼·카운터·원형 진행 표시)는 [plush](https://plush-ui.pages.dev/) (MIT)의 디자인 언어를 참고해 직접 구현했고, 색상은 중앙전파관리소 MI 전용색상(GOK Blue #003668, GOK Red #E6002D, GOK Gray #595757)에 맞췄습니다. 로고·기관명은 쓰지 않았습니다.

| 원칙 | 적용 |
| --- | --- |
| 시스템 상태 보여주기 | 첫 화면 "오늘 조사실" 카드: 지금 사용 중/비어 있음, 다음 예약, 오늘 예약률 링 · 시간표의 현재 시각 선 · 실시간 연결 표시 |
| 오류 예방 | 예약 시트가 그 날짜의 최신 예약을 다시 불러와 이미 찬 시간·지난 시간은 처음부터 못 고르게 함 · 이용 시간 최댓값을 다음 예약 전까지로 제한 |
| 기억보다 인식 | 조사관 드롭다운 대신 색 아바타 칩 · 마지막으로 고른 조사관 자동 선택 · 조사관별 고유 색을 모든 화면에서 동일하게 사용 |
| 사용자 통제와 자유 | 예약 취소·조사관 삭제 후 알림에서 바로 "되돌리기" |
| 현실 언어 사용 | 버튼에 "제출" 대신 결과를 그대로 표시 (예: "11월 18일 (수) 10:00–12:00 예약") |
| 미니멀 디자인 | 자주 안 쓰는 기능(데모 초기화·나가기)은 ⋯ 메뉴로 |
| 오류 복구 | 오류 메시지는 원인과 할 일을 쉬운 말로, 입력 위치 근처에 표시 |
| 접근성 | 모든 버튼 44px 이상, 키보드 포커스 표시, 스크린리더 레이블, 움직임 줄이기 설정 존중 |
| 개인정보 | "거래 품목" 칸 아래 "피조사자 이름·연락처는 적지 마세요" 안내 |

## 실행

```bash
npm install
npm run dev
```

환경변수(선택): `VITE_SUPABASE_URL`, `VITE_SUPABASE_KEY` (공개용 publishable 키)

DB 구성은 `supabase/schema.sql` 참고 (초대코드는 직접 정해서 넣기). Vercel 환경변수 `RR_CODE`(초대코드), `CRON_SECRET`은 매일 초기화 작업에만 사용합니다.
